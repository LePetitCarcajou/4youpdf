# Rapport de fin — rampe v0.5.0, session B

## 1. État des lieux et interface retenue

L'état des lieux est en tête de session ; l'interface retenue est celle proposée, sans changement. L'argument, en trois points :

- Deux emplacements différents parce que les deux portées diffèrent. Extraire agit sur la sélection : sa place est le menu contextuel des vignettes, l'interaction que l'ADR 0004 retient de PDF24 (point 2). Découper agit sur le document entier : sa place est la barre d'outils, à côté de Fusionner…, qui a la même portée.
- Le bandeau plutôt qu'une modale, et un bandeau vivant : il montre en permanence ce qu'il écrirait (« 3 fichiers : 5 + 5 + 2 pages. ») et suit la sélection et l'ordre, ce que l'ADR 0004 demande au point 6 — un champ numérique seul obligerait à l'essai-erreur.
- Les parties sont des tranches de l'ordre affiché, pas des plages du fichier. C'est pourquoi `ops::split` ne pouvait pas servir : ses `Range` visent les pages du fichier, alors qu'une page a pu être déplacée ou supprimée. Le côté Rust reçoit une liste d'indices par partie et appelle `ops::extract_pages` une fois par partie — sans rien ajouter au noyau.

## 2. Nouvelles commandes et permissions

| Commande | Permission | Pourquoi |
|---|---|---|
| `split_document(parts, dir)` | `allow-split-document` | Écrire une partie par fichier dans le dossier choisi, nommées d'après le document ; aucun fichier existant remplacé. Sur un thread bloquant, comme une rotation : une réécriture par partie. |
| `pick_folder()` | `allow-pick-folder` | Le sélecteur de dossier natif, ouvert côté Rust comme les trois autres : la page ne reçoit ni `dialog:default` ni aucun plugin `fs`. |

L'extraction n'a pas de commande à elle : elle réutilise `save_document`. L'opération est la même — la même liste d'indices passée à `ops::extract_pages`, le même fichier relu sans réparation avant d'être annoncé — et une seconde commande n'ajouterait aucune autorité (la page peut déjà écrire un chemin choisi) mais une seconde voie à maintenir. La description de `allow-save-document` est mise à jour pour que le manifeste reste vrai : « the whole document when saving it, the selected pages when extracting them ». Ce qui distingue extraire d'enregistrer est entièrement côté interface : le fichier écrit ne devient pas le point d'enregistrement.

`the_window_is_allowed_the_commands_of_the_interface_and_nothing_else` passe de 13 à 15 commandes, les trois listes (`COMMANDS`, `commands.toml`, `generate_handler!`) restant exactement égales.

## 4. Découpage en commits proposé

1. **`feat(app): cut the open document into files that replace nothing`**
   `app/src/session.rs`, `app/src/main.rs`, `app/permissions/commands.toml`, `app/capabilities/default.json`
   Pourquoi : le côté Rust ne savait écrire qu'un fichier à la fois. Le découpage porte sur l'ordre affiché, donc il reçoit une liste de pages par partie et non des plages : `ops::split` vise les pages du fichier. Aucun fichier existant n'est remplacé, et une partie que le noyau refuse laisse le dossier tel quel — d'où les noms confrontés au dossier d'abord, toutes les parties construites et relues ensuite, `create_new` enfin. L'extraction ne demande aucune commande de plus : `save_document` fait déjà exactement cela, et un test le fixe.

2. **`feat(ui): work out what extracting and cutting would write`**
   `app/ui/src/extract.ts`, `app/ui/src/split.ts`, `app/ui/tests/extract.test.ts`, `app/ui/tests/split.test.ts`, `app/ui/src/api.ts`
   Pourquoi : la lecture de N, les coupures et le partage de l'ordre se testent sans fenêtre ; les sortir de `main.ts` les met sous QuickJS avec le reste de la logique.

3. **`feat(ui): extract the selection and cut the document from the window`**
   `app/ui/src/main.ts`, `app/ui/src/notices.ts`, `app/ui/index.html`, `app/ui/styles.css`
   Pourquoi : le geste lui-même. Le réglage du découpage est un bandeau, jamais une modale (ADR 0004), traité par `submit` + `preventDefault` (`form-action 'none'`, ADR 0007) ; il montre son effet avant de l'appliquer et garde ses refus en place, parce que c'est le dossier ou le nombre qui doit changer. Ni l'extraction ni le découpage n'entrent dans l'historique.

4. **`docs(app): describe extracting a selection and cutting the document`**
   `app/README.md`, `docs/backlog-ui.md`

## 6. Ce qu'un script a déjà prouvé (ne pas refaire)

Sur le build de dev piloté par le port CDP, avec `mixed12.pdf` — 17 vérifications, toutes passées : les deux nouvelles entrées présentes dans la barre d'outils et le menu contextuel ; `split_document` accepté par la page (donc sa permission est bien accordée à l'exécution) et écrivant `mixed12_partie-01.pdf` (2 pages) et `-02.pdf` (1 page) ; le même découpage relancé refusé avec « « mixed12_partie-01.pdf », « mixed12_partie-02.pdf » existent déjà dans … ; aucun fichier n'a été écrit » ; `save_document` écrivant une sélection de 3 pages ; le bandeau qui apparaît, nomme le document, annonce « 2 fichiers : 10 + 2 pages. » puis « 3 fichiers : 5 + 5 + 2 pages. » quand le champ passe à 5 ; « 0 » refusé dans le bandeau sans rien écrire ; le document non marqué modifié après tout cela ; le second mode indisponible sans sélection, puis offert et compté (« (1 coupure) ») avec une page sélectionnée. Les trois fichiers produits ouverts ensuite par `fyp info` : PDF 1.7, xref classique, 2, 1 et 3 pages, aucune réparation.

Ce qu'aucun script ne prouve reste ci-dessous.

## 7. Checklist manuelle (à faire par Martin)

Sur le build de dev, avec `tests/fixtures/mixed12.pdf` :

- [ ] Sélectionner trois pages non contiguës, en tourner une, puis « Extraire la sélection… » : le fichier écrit contient ces trois pages, dans l'ordre affiché, avec la rotation.
- [ ] Après l'extraction, le document ouvert n'est pas marqué modifié (fermer la fenêtre ne pose aucune question s'il ne l'était pas avant).
- [ ] Sans sélection, l'action est indisponible : Ctrl+E ne fait rien et ne dit rien.
- [ ] Découper toutes les 5 pages : trois fichiers (5, 5, 2 pages), bien nommés, dans le dossier choisi.
- [ ] Découper avant les pages sélectionnées : les coupures tombent au bon endroit.
- [ ] Relancer le même découpage dans le même dossier : rien n'est écrasé, le bandeau nomme le conflit.
- [ ] Saisir « 0 », « abc » ou un nombre supérieur au nombre de pages pour N : message clair dans le bandeau, rien n'est écrit.
- [ ] Ouvrir les fichiers produits dans 4YouPDF et dans un autre lecteur : ils s'ouvrent sans avertissement.
- [ ] Clic droit sur une vignette : le menu montre « Extraire la sélection… » et les anciennes entrées fonctionnent toujours.
